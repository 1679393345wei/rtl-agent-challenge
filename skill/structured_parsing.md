# 结构化题面解析（structured_parsing）

> 载体：`agent/structured.py`（约 1067 行）
> 定位：Agent 增益的**主来源**——对题面中显式给出的真值表/状态表/状态图/波形表做确定性解析，直接合成可综合 Verilog，不经过模型。
> 来源：A 侧工作源码；本文由 C 依据源码结构与 10-07 交接总结整理。

---

## 一、为什么需要这一层

纯模型路线在两类题上系统性失分：

1. **题面把答案"写死"了**——K-map、状态转换表、波形表已经把行为完全确定，模型却仍要"猜"逻辑，容易写飘。
2. **硬题**（gshare、Lemmings、Conway、定时器等）逻辑复杂，模型单次生成的正确率很低。

结构化解析把第 1 类题变成**可复现的确定性求解**，从而把模型算力留给第 2 类。

**实测效果**：未见 49 题 `pass@5` 从 57.1%（28/49）提升到 95.9%（47/49）。

---

## 二、触发机制

```
generate_from_spec(prompt)
  → 依次尝试 26 个解析器（or 短路）
  → 任一命中：返回该解析器合成的 Verilog
  → 全部未命中：返回 None，交由模型生成
```

**设计红线**：

- **按题面特征触发，不按题号查答案**。解析器内部用正则匹配题面结构（如 `Read the simulation waveforms`、输入/输出端口清单、表格行格式）。
- **参考解与 testbench 不注入推理输入**，只用于诊断和验证。
- 结构化代码**只用于第一次尝试**；失败后的重试一律走模型（带错误反馈）。

## 四、验证方式

- **变体测试**：`tests/test_structured_variants.py` 含 **20 组独立合成变体**，在 iverilog/vvp 下全部通过。
- **变体覆盖**：穷举输入、one-hot 多状态位、不同位宽、规则表改变、时序优先级、方向恢复。
- **真实题直验**：新增规则命中的真实题 testbench 直验通过——Prob033、035、036、058、092、098、108、111、124、131、135、152。

**限制（须如实报告）**：

> 20 组变体**不是**对全部 26 个解析函数的全面形式化验证。解析器数量与测试方法数是两个概念，不能混为一谈（既不是"20 个模型"，也不是"20 类解析器"）。

## 五、失效条件

| 失效场景 | 说明 |
|---|---|
| 题面改写 | 解析器依赖题面结构特征；改写后触发可能失效或误触发 |
| 触发过宽 | 不完整/矛盾表格可能被误接管，产生错误代码且绕过模型兜底 |
| 波形采样歧义 | 波形推断只能得到「与有限观察一致」的候选行为，**不保证唯一电路** |
| 换数据集 | 8 道「纯组合 FSM」等特判针对当前数据集特征，需重新识别 |
| 异步复位 | 解析器若默认同步复位语义，遇到异步复位题需单独处理 |

**下一步（对应设计报告优先级 3）**：通用解析器审计与阴性测试——确保不完整/矛盾表格、异步复位、采样歧义**不误接管**，并保留失败证据。

## 六、与提示词工程的关系

结构化解析命中时**完全绕过提示词**；未命中时仍走分类模板 + 引导解码 + 反馈重试。

因此，**提示词工程的收益被结构化解析"吃掉"了一部分**——原本靠提示词勉强能过的题，现在被确定性解析直接解决。这也解释了为什么 FSM few-shot、温度多样化等提示词路线实测**没有稳定增益**（详见 `pitfalls_phase3.md`）。
