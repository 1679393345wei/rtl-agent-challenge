# 阶段2 踩坑记录（Agent 重试循环）

> 记录 agent.py 主循环开发中遇到的问题与解决方案。
> 对应方案阶段2：Agent 重试循环（错误提取、上下文管理、温度调参、超时保护）。

---

## 错误提取精度

### pitfall-01: vvp 仿真输出被 VPI 噪声淹没，无法直接喂给模型

**现象：**
直接把 `vvp` 的完整 stdout 作为错误信息注入回模型，重试几乎无效——模型被大量无关行干扰，抓不到真正的失败原因。

**根因：**
iverilog 仿真输出里除了判题用的 `Hint:` 行，还混有大量 VPI 内部调用信息（形如 `%vpi_call/w 3 93 "$display", ...`），这些是工具链的调试噪声，不是电路错误。

**解决：**
`error_parser.py` 只提取两类关键信息：
1. 编译错误：`iverilog` 报错的**行号 + 消息**。
2. 仿真 mismatch：匹配 `Hint: Output '<信号名>' has <N> mismatches. First mismatch occurred at time <T>.` 这一行，取出「哪个信号、错了几位、首次错在哪一时刻」。

最终注入模型的错误描述控制在 **<200 tokens（1~3 句）**，只留「错在哪、错多少」，去掉 VPI 噪声。改后重试命中率明显提升。

## 上下文管理

### pitfall-02: 重试历史无限累积导致 token 爆炸、超时

**现象：**
最初把「首轮代码 + 每轮错误 + 每轮修正代码」全部塞进上下文，跑到 4~5 轮后单题耗时失控，甚至触发仿真超时。

**根因：**
多轮对话式重试会线性膨胀 prompt 长度，既浪费推理时间，又让模型注意力被早期的错误代码分散。

**解决：**
上下文只保留两样东西：
- **首轮的题目 + 原始生成代码**（保持任务锚点）；
- **最新一轮的错误摘要**（只带最新失败原因）。

即「首轮 + 最新错误」策略，丢弃中间修正历史。这样每轮重试的输入长度稳定，单题总耗时可控。

## 温度调参

### pitfall-03: FSM 对 temperature 高度敏感（交叉引用阶段0）

**现象：**
temperature=0.6 下，FSM 通过率在 **41% ~ 14%** 之间大幅波动（详见 `pitfalls_phase0.md`）。

**根因：**
FSM 题依赖精确的状态转换真值表，高温下采样更随机，状态机逻辑更容易写飘。

**解决：**
Agent 第 3 轮以后的重试用较低温度（0.3 或更低），用「高温探索、低温收敛」的策略。稳定性实验最终也统一到低温度。

## 超时保护

### pitfall-04: 单题卡死拖垮整轮 156 题跑批

**现象：**
个别题在某轮重试中卡在编译或仿真，一路拖到 vLLM 超时，导致整批评测卡住。

**根因：**
模型可能生成死循环相关电路，或 vLLM 生成长时间不返回，缺少单题级的兜底。

**解决：**
给每道题加 **5 分钟单题超时**，超时判定为 `timeout` 后进入下一题；重试轮数上限 5 轮。这样 156 题能从「从一而终」跑完不崩。

---

## 小结

| 问题域 | 根因 | 关键解法 |
|---|---|---|
| 错误提取 | VPI 噪声淹没判题信息 | 只抓 `Hint:` 行 + 编译错误行号，<200 tokens |
| 上下文管理 | 重试历史线性膨胀 | 只留「首轮 + 最新错误」 |
| 温度调参 | FSM 对温度敏感 | 高温探索、低温收敛（0.3） |
| 超时保护 | 单题卡死拖垮跑批 | 单题 5min 超时 + 最多 5 轮 |
