> 赛道：3.1 RTL/HLS 本地智能体设计赛道（RTL 子赛道）
> 模型：QiMeng-SALV-7B（LoRA v2 合并权重）　·　数据集：VerilogEval v2（spec-to-rtl，156 题）

---

## 1. 项目概述

本项目构建一个 **RTL 本地智能体**，在 VerilogEval v2 的 156 道题上自动完成 Verilog 代码生成、编译、仿真与判题，并最大化通过率。

系统的增益来自**两层叠加**：

1. **确定性题面解析层**（`agent/structured.py`）：对题面中显式给出的真值表、状态表、状态图、波形表做结构化解析，直接合成可综合 Verilog，不经过模型。
2. **Agent 闭环层**（`agent/runner.py`）：结构化未命中时调用模型生成，编译/仿真失败后携带错误摘要重试，最多 5 轮。

### 核心指标

| 指标 | 基线（纯模型） | 定稿 FULL05A | 定稿 FULL05B |
|---|---|---|---|
| 全量 156 题 pass@5 | 60.9%（95/156） | **76.9%（120/156）** | 76.3%（119/156） |
| 未见 49 题 pass@5 | 57.1%（28/49） | **95.9%（47/49）** | 93.9%（46/49） |
| 已见 107 题 pass@5 | 62.6%（67/107） | 68.2%（73/107） | 68.2%（73/107） |
| 未见 49 题首发通过率 | — | 93.9%（46/49） | 89.8%（44/49） |
| 已见 107 题首发通过率 | — | 65.4%（70/107） | 63.6%（68/107） |

> **指标定义**：本项目 `pass@5` 指「最多五次带反馈的尝试中至少一次通过」，属 Agent 工作流成功率；`首发通过率`（CSV 中记作 `pass_at_1`）指第一次尝试即通过。二者都不能等同于论文用多次独立采样估计的 `pass@k`。

**证据限制（须一并报告）**：49 道「未见」题指未进入 LoRA 训练，但它们已反复参与解析规则开发与选择。因此 93.9%~95.9% 属本地诊断与回归成绩，**不是独立隐藏题成绩**；全量成绩含训练题记忆，不作为泛化主指标。

## 2. 系统架构

评测链路：

```
题目(prompt.txt)
  → classifier.classify()            按题面判定 combo / seq / fsm / complex
  → structured.generate_from_spec()  26 个确定性解析器依次尝试
        ├─ 命中 → 直接合成 Verilog（不经模型，结果可复现）
        └─ 未命中 → vLLM chat（SALV-7B + guided_regex 引导解码）
  → extract_module()                 提取 module TopModule ... endmodule
  → iverilog v12 三文件编译（生成代码 + *_ref.sv + *_test.sv）
  → vvp 仿真，解析 "Mismatches: 0 in ..." 判 pass/fail
  → 失败 → error_parser 提取精简错误 → 注入重试（最多 5 轮，温度 0.3×5）
  → 输出 val_<TAG>.csv + traces/ + run_config.json
```

关键设计点：

- **结构化优先、模型兜底**：结构化代码只用于第一次尝试；失败后的尝试一律走模型（带错误反馈）。
- **引导解码**：chat 模式下默认启用 `guided_regex=(?s)module\s+TopModule.*endmodule`，强制模型直接产出完整模块。全量 156 题实测 `pass@5` 91→96、`pass@1` 82→86；后端不支持该参数时自动降级重发，避免整题失败。
- **双验证后端**：`iverilog`（功能仿真主口径）与 `vivado`（综合/资源/时序检查）可切换；功能成绩以 iverilog/vvp 为准。
- **评测可信度**：已移除对题面的 2048 字符截断，传递完整题面；每次尝试保存题号、次数、配置、来源、生成代码、编译与仿真输出；使用唯一 `RUN_TAG` + 排他锁 + 防覆盖检查，`run_config.json` 记录 runner 与 structured 源码 SHA256。

## 4. Agent 设计

### 4.1 结构化题面解析（增益主来源）

`agent/structured.py` 共 **26 个解析函数**（由 `generate_from_spec()` 依次触发），按题面特征匹配，**不按题号查答案**；参考解与 testbench 只用于诊断和验证，不注入推理输入。

| 类别 | 已实现行为 |
|---|---|
| 组合与真值表 | K-map Gray-code 展开；完整组合波形表；相邻位向量；signed overflow；组合子模块；互斥模式输出；XOR 三种实现 |
| FSM | one-hot 逐位入边方程；状态表与状态图；命名 Moore 表；两状态 Moore；二进制下一状态位 |
| 波形与计数 | 装载递增回绕；高电平旁路与下降沿采样；反相触发器；1~10 计数；12 小时钟 |
| 复杂时序 | 串行补码、串行接收；gshare；Lemmings 跌落/挖掘/死亡；Conway Life；Rule 90/110；定时器 |

验证：`tests/test_structured_variants.py` 含 **20 组独立合成变体**，在 iverilog/vvp 下全部通过。变体覆盖穷举输入、one-hot 多状态位、不同位宽、规则表改变、时序优先级与方向恢复。**注意：这不是对全部 26 个解析函数的形式化验证。**

### 4.2 错误解析与重试循环

1. **错误解析**（`agent/error_parser.py`）：`parse_compile_error()` 提取 iverilog 报错行号与消息；`parse_sim_mismatch()` 提取 mismatch 的信号名与首次出错时刻；`parse_error()` 统一压缩为 <200 tokens 的精简描述，过滤 VPI 噪声。
2. **重试循环**（`agent/runner.py`）：编译失败与仿真失败均触发重试，最多 5 轮；温度定稿为 0.3×5（消融实测 0.2→1.0 多样化无增益，故不做升温）。
3. **重试提示**（`agent/prompts.py`）：按错误类型注入定向自查清单——`[SIM ERROR]` 提示核对状态寄存器时钟边沿/次态组合逻辑/复位语义/输出全分支赋值；`[COMPILE ERROR]` 提示 Verilog-2001 语法、端口列表逗号、子模块定义、信号声明冲突。
4. **超时保护**：单题 5 分钟超时，保证 156 题全量跑批不崩溃。

### 4.3 效果归因

| 手段 | 作用 |
|---|---|
| 结构化解析 | 硬题（K-map、one-hot FSM、gshare、Lemmings、Conway、时钟、串行数据、定时器）从模型不可解变为确定性可解 |
| 引导解码 | 消除「输出不含完整模块」类失败 |
| 重试循环 | 压缩语法与行为错误；对行为错误有边际改善 |
| 提示词工程 | **无稳定增益，已回退**（见第 5 节） |

## 5. 提示词工程（含已证伪路线）

### 5.1 分类模板

`agent/prompts.py` 保留四类模板（`SYSTEM_COMBO` / `SYSTEM_SEQ` / `SYSTEM_FSM` / `SYSTEM_COMPLEX`），由 `classifier.classify()` 按题面切换：

| 模板 | 核心约束 | 类别（题数） |
|---|---|---|
| combo | assign / always@(*)、所有分支赋值、禁 always_ff | 组合（81） |
| seq | always@(posedge clk)、复位写在块内而非敏感列表 | 时序（38） |
| fsm | localparam 编码、case 带 default、非阻塞赋值、复位写在块内 | FSM（29） |
| complex | 层次化输出所有子模块（TopModule 最后）、禁类型转换 | 综合（8） |

> 分类口径统一为 `problem_classification.csv`：**组合 81 / 时序 38 / FSM 29 / 综合 8**。8 道「纯组合 FSM 题」（Prob079/091/099/100/134/135/143/150）原被结果脚本按名称归为 fsm，实为纯组合逻辑，已划归组合类。

### 5.2 提示词消融结论

在统一口径 `pass@1` 复测下（C/B 链路）：

| 版本 | pass@1 | FSM 分项 | FSM 模板规则数 |
|---|---|---|---|
| 裸模型基线 | 51.92% | 31.03% | — |
| B_v6 | 51.28% | 31.03% | — |
| B_v7 | 55.77% | 20.69% | — |
| **B_v8** | **58.97%（峰值）** | **41.38%（FSM 峰值）** | 11 |
| B_v9 | 58.33% | 31.03% | 9 |
| B_v10 | 56.41% | 20.69% | 9 |
| B_v11（温度 0.2） | 54.49% | 17.24% | 11 |
| Agent 定稿（v12） | 58.33%（91/156） | 20.69%（6/29） | 9 |

**分项（统一口径 81/38/29/8）**：

| 类别 | 基线 | Agent | 变化 |
|---|---|---|---|
| 组合（81） | 70.37% | 72.84% | +2.47 ↑ |

### 5.3 已停止的路线（重要负结果）

| 路线 | 结果与处理 |
|---|---|
| 增加 140 条 repair 训练样本 | v3 为 25/49，51.0%；低于 v2，**弃用** |
| LoRA rank 8 → 32 | v4 为 27/49，55.1%；未提高泛化，**弃用** |
| 改重试诊断提示 | 两轮均 26/49，对照均 28/49；**已回退** |
| 温度多样化、FSM few-shot | 没有稳定收益；**保留 0.3×5 与原提示策略** |

> 独立复测佐证：C 侧曾单独用 FSM 专用提示词（B_v8 11 条 / 精简 5 条 / 增强 13 条）在 29 道 FSM 题上对比，结果 17.2%~31.0%，均**低于**同口径基线，且规则越多越差。该结论与 A 侧「FSM few-shot 无稳定收益」一致，**FSM 专用提示词已判定为负收益**。

## 7. 失败分析

定稿后仅余 3 道未完全解决：

| 题目 | FULL05 A/B | 归因与处理 |
|---|---|---|
| Prob053_m2014_q4d | 失败 / 失败 | 无复位 XOR 反馈触发器未指定初值；参考实现初始化为 0。**保留题面缺失说明，不把参考初值硬编码进规则** |
| Prob099_m2014_q6c | 失败 / 失败 | 题面/参考输出 Y1/Y3，测试连接 Y2/Y4；**保持原数据，单独报告测试接口缺陷** |
| Prob136_m2014_q6 | 通过 / 失败 | reset 端口存在，但题面未明确复位目标；仍依赖模型，**不能宣称完全修复** |

**主要瓶颈已从「语法错误」转为「题面歧义」**：基线阶段 compile_fail 曾高达 70 题（iverilog v10.3 不支持 SystemVerilog `logic`），升级 v12 后编译失败降至个位数；结构化解析进一步消除了大部分行为错误。

**不能据此声称已优化到理论极限**。隐藏题、题面改写、解析触发过宽、波形采样歧义和参考初始状态都可能暴露新问题。尤其波形推断只能得到「与有限观察一致」的候选行为，不保证唯一电路。

## 9. 大模型协作记录

团队三名成员分工：A（模型、Agent 核心、评测与交付）、B（协作入口、提示模板与评测衔接）、C（仓库管理、数据集入库、文档报告与技能包汇总）。

AI 辅助贯穿本项目的文档与数据侧（主要由 C 使用）：

- **数据提炼**：从服务器 `results/*.csv`、`logs/*.log` 中只读抽取 pass@1、分项通过率、失败分布、消融与稳定性数据，汇总成 `skill/` 下的 markdown 存档。
- **失败分析**：对比 FSM 倒退题的基线/Agent 代码 diff 与仿真错误摘要，归纳系统根因。
- **报告撰写**：起草设计报告、踩坑清单、提示词库等文档，再由人工核对数据口径与结论。
- **口径统一**：识别并修正 `problem_classification.csv` 与结果 CSV 的题型归属差异（8 道纯组合 FSM 题）。

**协作分工原则**：AI 负责「归纳、对比、起草」，队员负责「跑实验、定口径、审结论」；所有数字均以服务器 CSV 为准，AI 不直接改动实验产物。

## 10. 结论与展望

1. **两层增益结构成立**：确定性题面解析（26 个解析器）承担主要泛化增益（未见 49 题 +36.7~38.8pp），Agent 闭环（引导解码 + 5 轮反馈重试）进一步压低失败率。全量 156 题 `pass@5` 从 60.9% 提升到 **76.9%**。
2. **提示词工程路线已证伪**：分类模板保留用于模型兜底，但 FSM few-shot、温度多样化、repair 训练样本、LoRA 升 rank 均无稳定收益，已回退。
3. **剩余失败集中在题面歧义**（Prob053 缺初值 / Prob099 测试接口不一致 / Prob136 复位目标未明确），不是模型能力问题。
